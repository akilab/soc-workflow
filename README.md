# SOC Workflow

SOC のインシデント対応フローを、**設計する道具**と、**対応者が辿る配布物**の
両方にする。Excel の手順書を置き換えることが目的。

実行ファイル 1 つで動く。データは手元の JSON ファイル 1 つ。外部へは何も送らない。

---

## 何ができるか

### 1. フローを図で組み立てる

対応フローを、**列＝担当・行＝実施順**の図として組み立てる。ボックスをドラッグして
置くと、置いた列がそのまま「誰がやるか」に、置いた高さが「何番目にやるか」になる。

線は必ず下へ進み、決して戻らない。行 i の線は行 i と i+1 のあいだしか通らないので、
**接続線が交差することが構造的に起こらない**。迷路のような図にならない。

### 2. 条件分岐を、対応者に解かせない

「〇〇だったらここは飛ばして□□へ」を、判断ステップとして図に持たせる。
配布物の側では、対応者が答えを選ぶと**その先に関係のない手順は消える**。
辿るべき道が 1 本だけ残る。

### 3. 部品を組み合わせて作る

フェーズ・対応・連絡先は**フローをまたいで共有する部品**として 1 か所に持つ。
フローはその組み合わせとして作る。「エスカレーション先の電話番号が変わった」ときに
直す場所は 1 か所で済む。

### 4. 顧客ごとの違いを見える形で持つ

共通フローから顧客別フローを作れる。何を足して何を外したかがいつでも見られ、
共通フローがあとから更新されたときは印が出る。

### 5. 配る

**外部を一切参照しない単一 HTML** に書き出す。CDN も Web フォントも使っていない。
ファイルをコピーするだけで配れる。対応者は開いて上から辿るだけでよい。

## 使い方

### 起動

実行ファイルを置いてダブルクリックするだけ。必要なものは他に何もない。

```
soc-workflow.exe
```

```
SOC Workflow
  データ: C:\...\soc-workflow.json
  中身:   フェーズ 5 / 対応 48 / 連絡先 14 グループ・25 名 / フロー 5・手順 59
  URL:   http://127.0.0.1:8765/
終了するには Ctrl+C。
```

ブラウザで `http://127.0.0.1:8765/` を開く。**データファイルは初回に自動で作られる**
（実行ファイルの隣）。2 回目からはそれを読む。

| 旗 | 意味 |
| --- | --- |
| `--empty` | 種データを入れず、空から始める（ファイルがまだ無いときだけ効く） |
| `--data <path>` | データファイルの場所を変える |
| `--addr <host:port>` | 待ち受け先を変える（既定 `127.0.0.1:8765`） |

最初から入っているフローは**ダミー**で、実運用の手順ではない。自分たちのものを
一から作るなら `--empty` で始めるとよい。

### 画面

左の帯に 3 つ。**フロー**（対応フローの一覧）、**対応**（部品の一覧）、
**連絡先**（連絡順を持つグループ）。左上の点の集まりは、外部の画面への
リンク集（Defender や Intune など。自分で足せる）。

フローを開くと編集ビューになる。左が**手順アウトライン**（縦に読む）、
中央が**フローキャンバス**（図）、右が**インスペクタ**（選んだ手順の中身）と
**対応パレット**（置ける部品）。

### 最初の一歩（空から始めた場合）

1. フロー一覧の**フェーズ設定**で、対応のフェーズを並べる
   （受信・確認 → 情報収集 → 封じ込め → 復旧 → 記録・報告 など）
2. **担当設定**で、図の列にする担当を並べる（顧客 / Tier1 / Tier2 / CSIRT など）
3. **対応**画面で、フローに置く部品を作る
4. フロー一覧の**作成**でフローを 1 本作る
5. 編集ビューの**対応パレット**から、キャンバスへドラッグして投入する

### 手元で使うキー

| | |
| --- | --- |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 取り消す / やり直す（全画面で効く） |
| `Ctrl+ホイール` | フローキャンバスの拡大縮小（50〜200%） |
| `Esc` | 開いている面を閉じる |
| ドラッグ | 手順の担当と順番を同時に変える |

### 配る

編集ビューの**エクスポート**から、単一 HTML を書き出す。プレビューで実物を
確認してから保存できる。フロー一覧のエクスポートは全フローをまとめて 1 つにする。

書き出した HTML は**外部を一切参照しない**。社内のファイルサーバに置いても、
メールで送っても、そのまま開ける。

## 決めごと

この道具が守っている約束。理由は `PROJECT-BRIEF.md` と `docs/SPEC.md` に書いてある。

- **外部へ送らない。** データは手元の JSON だけ。ネットワークへは何も出さない
- **書き出す HTML は外部参照ゼロ。** CDN も Web フォントも使わない
- **色だけに頼らない。** 状態は記号と言葉でも示す
- **接続線は右から出て左から入る。** 交差が起きない配置を構造で保証する
- **判断ステップには完了ボタンを出さない。** 答えないと先へ進めない

## 作る

必要なのは **Go だけ**。Node は要らない（フロントエンドの組み立てに使う esbuild は
Go の依存として入る）。

```bash
go run ./cmd/build-web && go build -o soc-workflow.exe .
```

`cmd/build-web` が `web/` の TypeScript と CSS を `internal/web/dist` へ組み立て、
`go build` がそれを実行ファイルに埋め込む。**dist はコミットする**（無いと
`go build` が通らないため）。

型検査（任意）:

```bash
npx -y -p typescript@5 tsc --noEmit -p web
go test ./...
```

他の OS へ:

```bash
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -o soc-workflow .
```

## 注意

- **手元で動かす前提で作ってある。** `127.0.0.1` 以外からの要求は断る。認証は無い。
  サーバに置いて複数人で共有する使い方は想定していない
- **対応フローは「どこを見ていて、どこを見ていないか」の情報を含む。**
  実データを入れたファイルの扱いには注意する。ダミーと実データを混ぜない
- ブラウザは Chromium 系（Edge / Chrome）を想定。`color-mix()`・CSS の `zoom`・
  `:has()` を使っている
